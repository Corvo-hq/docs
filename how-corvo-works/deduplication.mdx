---
title: "Repeated alerts"
description: "How Corvo handles redelivery and recurring errors."
---

Corvo avoids storing the same Cloud Logging entry twice when Pub/Sub redelivers it with the same `insertId`. Other occurrences are retained, even when they have the same error fingerprint. They can be counted in a report and assigned to an investigation.

After a collection window closes, the orchestrator groups alerts by likely cause. It can give new alerts to an existing investigation, allowing its agent to use what it learned earlier, or start a new one. A past PR may inform that decision, but an open PR does not automatically suppress a new alert or agent run.

**Example:** A service writes the same exception seven times across several windows. Corvo keeps the seven occurrences and may show them under one continuing investigation. The agent can check whether the cause or impact has changed. It may report the recurrence without opening another PR.

See [Investigation pipeline](/how-corvo-works/investigation-pipeline) for the full flow.

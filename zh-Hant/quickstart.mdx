---
title: "快速入門"
description: "連接通知管道、GitHub 和 Google Cloud，開始接收調查結果。"
---

開始前，請確認你有 Corvo 工作區、GitHub App 安裝權限，以及設定 Google Cloud 專案 IAM 與日誌接收器的權限。整合設定由管理員操作；角色權限請參閱[工作區](/zh-Hant/workspace)。

## 1. 連接通知管道

開啟 **Integrations**。你可以連接 **Telegram bot** 的私訊或群組，也可以[綁定 Discord 頻道](/zh-Hant/integrations/discord)。Telegram 的對話 Bot 與告警 Bot 分開連接；綁定對話 Bot 後，還要連接告警 Bot 才會收到調查通知。每個工作區只能有一個有效的 Telegram 對話目的地。

**確認：**Telegram 顯示已連接的對話與告警目的地，或 Discord 顯示 **CHANNEL BOUND**。

## 2. 準備 GitHub

開啟 **Integrations → GitHub**，安裝 Corvo GitHub App，並選擇可授權的帳號與儲存庫。接著在 **Agent environment**：

1. 對每個要讓 Corvo 使用的儲存庫選擇 **Add repo**。
2. 為每個儲存庫填寫設定指令。指令會從儲存庫根目錄執行；環境預先提供 Node、Git 與 `gh`，其他工具須由指令安裝。
3. 選擇 **Save & build**，等狀態變成 **READY**。

GitHub App 的安裝範圍是可存取的上限；Agent environment 才決定 Corvo 會預先準備哪些儲存庫。詳細操作請參閱 [GitHub 設定](/zh-Hant/integrations/github)。

## 3. 連接 Google Cloud

開啟 **Integrations → GCP Cloud Logging → Manage**，輸入專案 ID。Cloud Logging 讀取權為必要項目；Cloud Run、Cloud Monitoring 和 Cloud Trace 的讀取權可依調查需求選擇。接著完成六個步驟：

1. 啟用頁面列出的 API。
2. 建立或沿用 `corvo-agent` 服務帳戶，不需建立金鑰。
3. 將 Corvo 列出的讀取角色授予該帳戶。
4. 在 `corvo-agent` 的 **Principals with access** 分頁，將 **Service Account Token Creator** 授予 Corvo 的執行身分。
5. 選擇 **Bind & Verify**，等所有檢查通過。
6. 選擇最低嚴重程度，以及至少一項 Cloud Run、GKE 或 Compute Engine 來源。依 Corvo 顯示的目的地與篩選條件建立 `corvo-alert-sink`；也可使用 **Script · gcloud** 模式。選擇 **Connect**，再選擇 **Finish**。

第一個畫面的讀取權選項與第六步的日誌串流範圍是兩回事。只選擇你要傳送至 Corvo 的資源。Google Cloud Console 的詳細操作請參閱 [Google Cloud 設定](/zh-Hant/integrations/google-cloud)。

**確認：**專案顯示 **CONNECTED**，告警串流顯示 **STREAMING**，且 Active filter 符合所選來源。

## 4. 追蹤調查

收到符合條件的錯誤後，開啟 **Investigations**。同一原因的告警會整理到一項調查。你可以查看狀態、告警、調查結果、Cloud Logging 連結及已記錄的 PR。調查完成後不一定會建立 PR。詳見[調查頁面](/zh-Hant/features/incident-response)。

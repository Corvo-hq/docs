## 從告警到處理結果

Corvo 收到符合條件的告警後，會先檢查同一錯誤是否曾經發生，再決定是否開始調查。調查時會使用可存取的 Google Cloud 資料，以及受影響服務所對應的儲存庫。

處理結果可能包含調查發現、Telegram 更新及修正 Pull Request。是否建立 PR 會依調查結果、服務對應、儲存庫存取權與 Agent 權限而定。

## 準備服務

先完成[快速入門](../quickstart)，連接 Telegram、GitHub 與 Google Cloud。接著在 Google Cloud 整合頁面，將 Cloud Run 服務綁定至對應儲存庫。

若未設定儲存庫對應，Corvo 仍會回報調查發現，但不會建立修正 PR。

## 檢視事件

在側欄開啟 **Incidents**。事件表格會顯示時間、專案、Revision、Policy、處理狀態及可用連結。

使用連結開啟對應的 Google Cloud 日誌或產生的 Pull Request。部分事件可能沒有 PR 或日誌連結，此時按鈕會顯示為停用狀態。

**COMPLETED** 代表該次處理流程已結束。請檢視調查發現與 PR，確認造成事件的錯誤是否已修復。

## 檢視修正內容

開啟連結的 PR，檢查程式碼變更與驗證結果。Corvo 是否能建立分支、推送 Commit 及建立 Draft PR，取決於 **Permissions** 中的設定。

## 錯誤再次發生時

Corvo 可能只記錄近期的重複事件、提醒團隊已有尚未關閉的 PR，或在先前修正 PR 已關閉或合併後重新調查。請參閱[重複告警處理機制](../how-corvo-works/deduplication)中的範例。
